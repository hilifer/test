# 测试用例 · YAORONG LED / YR GRID 独立销售站

> 本文件列出所有自动化测试用例。编号与测试代码一一对应：在 `tests/` 下搜索编号（如 `SF-05`）即可找到对应的测试代码。
> 每次推送代码到 GitHub，**GitHub Actions** 会自动运行全部用例（工作流：`.github/workflows/yr-sites-ci.yml`），结果汇总显示在该次运行的 Summary 页面。

## 一、怎么运行

| 命令（在 `yr-sites/` 目录） | 内容 | 用时 |
|---|---|---|
| `pnpm test` | 单元测试 + 接口测试（2146 条，每条只验证一个行为） | 约 1 分钟 |
| `pnpm build && pnpm test:e2e` | 两个站点构建后，用 Chromium 浏览器做端到端测试（桌面 35 条 + 手机 6 条）；加 `E2E_VIDEO=1` 录制每条流程 | 约 2 分钟 |
| `pnpm build && pnpm test:demo` | 录制演示视频：两个网站每个页面、网店每个页面、后台每个页面各一段，加 10 段按岗位的功能演示，生成 `test-results/demo/index.html` | 约 30 分钟 |
| `node --test tests/live/` | 连接真实第三方服务（沙箱）的测试，没有配置密钥的自动跳过 | 约 1 分钟 |
| `bash scripts/prod-stack.sh up` 后 `E2E_EXTERNAL=1 pnpm exec playwright test --project=desktop` | 用生产 Docker 镜像 + 生产 Caddy 配置启动两个站，再跑浏览器测试 | 约 10 分钟 |
| `pnpm test:all` | 单元、接口、构建、端到端 | 约 3 分钟 |
| `bash scripts/docker-smoke.sh led`（或 `grid`） | 按生产方式构建 Docker 镜像并启动，检查健康、文章导入、站点构建、对话、后台登录 | 首次约 2 分钟 |
| `pnpm stack` | 本地同时启动两个站（LED :4311，GRID :4312），后台账号 `admin` / `e2e-pass` | — |

### GitHub 上的运行方式

每次推送，GitHub Actions 按下面的任务分别运行，每个任务在运行页面单独显示结果：

| 任务 | 内容 |
|---|---|
| Unit tests | 全部单元测试 |
| API tests (a-l / m-z) | 黑盒接口测试，分两组并行，每个测试文件启动真实服务器 |
| Browser E2E (recorded) | 桌面 + 手机浏览器测试，每条流程都录像 |
| Demo videos | 每个页面、每个功能的演示录像（带中文字幕条） |
| Docker smoke (led / grid) | 生产镜像启动冒烟 |
| E2E on the production image | 生产镜像 + 生产 Caddy 配置启动两个站，跑全部桌面浏览器测试 |
| Live services | 真实的 Claude、Stripe 测试模式、PayPal 沙箱、企业微信、SMTP、17TRACK、金蝶沙箱（见下文“真实第三方服务”） |
| Report | 汇总：Summary 页面按模块列出**每一条用例**的结果和用时；“yr-sites test cases”检查项也逐条列出；`demo-videos` 附件里是全部录像和索引页 |

**查看演示视频**：打开某次运行 → 页面底部 Artifacts → 下载 `demo-videos` → 解压后用浏览器打开 `index.html`，按“功能演示 / 后台页面 / 网站页面 / 端到端流程”分组，可搜索，每段视频可直接播放。

**真实第三方服务**：在仓库 Settings → Secrets and variables → Actions 添加下面的密钥后，Live services 任务会连真实服务测试；没有添加的项显示为“跳过”，不会伪造通过。只使用测试 / 沙箱账号（Stripe 只接受 `sk_test_` 开头的密钥）。

| 服务 | Secrets（Variables 可选） |
|---|---|
| Claude（或其他大模型） | `LIVE_LLM_API_KEY`；Variables：`LIVE_LLM_PROVIDER`（默认 anthropic）、`LIVE_LLM_MODEL` |
| Stripe 测试模式 | `LIVE_STRIPE_SECRET_KEY`（sk_test_…） |
| PayPal 沙箱 | `LIVE_PAYPAL_CLIENT_ID`、`LIVE_PAYPAL_CLIENT_SECRET` |
| 企业微信群机器人（测试群） | `LIVE_WECOM_WEBHOOK_URL` |
| SMTP | `LIVE_SMTP_URL`；Variables：`LIVE_MAIL_FROM` |
| 17TRACK | `LIVE_TRACK17_KEY` |
| 金蝶云星空沙箱 | `LIVE_KD_BASE`、`LIVE_KD_ACCT`、`LIVE_KD_USERNAME`、`LIVE_KD_APP_ID`、`LIVE_KD_APP_SECRET`；Variables：`LIVE_KD_ORG` |

后台账号：部署时设置的 `ADMIN_USER` / `ADMIN_PASSWORD` 是初始管理员，登录后在“账号权限”页为每位同事建账号并分配角色。

在 **GitHub Codespaces** 中打开仓库，会自动安装依赖、浏览器并构建站点，然后直接运行上面的命令即可（配置：`.devcontainer/devcontainer.json`）。

## 二、测试分层与隔离方式

| 层 | 位置 | 做法 |
|---|---|---|
| 单元测试 | `tests/unit/` | 直接调用模块函数。每个测试文件在独立进程中运行，使用独立的临时数据库和文章目录 |
| 接口测试（黑盒） | `tests/api/` | 每个文件启动一个真实的销售服务器进程（临时数据库、随机端口），通过 HTTP 调用，和业务员、客户的实际使用方式一致 |
| 浏览器 E2E | `tests/e2e/` | 先构建两个站点的静态页面，再启动"静态站 + 后端"，用 Playwright 驱动 Chromium，按客户的操作路径点击 |
| 部署冒烟 | `scripts/docker-smoke.sh` | 构建生产镜像，挂空数据卷启动，验证首次启动流程 |

**外部系统一律用模拟服务器代替，测试不会产生费用、不会碰真实数据：**
大模型接口（Claude / OpenAI 兼容）、金蝶云星空 WebAPI、企业微信 / 飞书机器人、行业新闻 RSS、IndexNow，都用 `tests/helpers/mock-http.mjs` 模拟，并检查我方发出的请求内容是否正确。

## 四、本次测试发现并已修复的问题

| # | 问题 | 影响 | 修复 | 对应用例 |
|---|---|---|---|---|
| 1 | 后台没有 CSRF 防护 | 后台用 Basic 认证，浏览器会自动带上凭据；业务员登录后访问恶意网页，就可能被诱导改订单状态、登记收款 | 后台写操作校验请求来源，跨站提交返回 403 | AD-06 |
| 2 | 导出 CSV 存在公式注入 | 公开表单填 `=HYPERLINK(...)` 等内容，业务员用 Excel 打开时会被当成公式执行 | 以 `= + - @` 开头的单元格前加单引号 | AP-14 |
| 3 | 调用 Claude 时传了 `temperature` | 新版 Claude（Opus 4.7 及以后、Sonnet 5.5）会直接返回 400，内容智能体和 GEO 监测接入新版 Claude 后会全部失败 | 调用 Claude 时不再传该参数（OpenAI 兼容接口照旧） | CA-17 |
| 4 | RSS 摘要解码顺序有误 | 很多新闻源的摘要是转义过的 HTML，解码后残留 `<p>` 等标签，被送进写稿输入 | 解码实体后再去一次标签 | CA-08 |
| 5 | 对话的 `max_tokens` 默认只有 900 | 新版 Claude 的思考过程也计入上限，回复容易在出正文前被截断，客户只看到兜底追问 | 默认值调到 4000（按实际用量计费，可用 `LLM_MAX_TOKENS` 调整） | — |
| 6 | 伪造请求头可绕过限流 | 可被用来刷大模型费用、刷垃圾线索 | 只认 Caddy 追加的真实 IP | AU-15 |
