# 耀嵘独立站 · 部署与运营手册

两个独立销售站共用一套代码：

| 站点 | 品牌 | 语言 | 服务器 | 主要转化入口 |
|---|---|---|---|---|
| 外贸 LED 照明 | YAORONG | 英文 | 北美（建议美西：洛杉矶 / 俄勒冈） | 首页选型器 + AI 即时报价 |
| 光伏 · 储能 · 充电桩 | YR GRID | 英文 + 中文 | 东南亚（建议新加坡） | 收益测算器 + AI 即时报价 |

每个站部署在**一台独立服务器**上，数据互不相通。

---

## 一、整体架构

```
访客 / 采购方的 AI 智能体
        │ HTTPS
   ┌────▼─────────────────────────── 一台服务器（Docker）───────────┐
   │  Caddy（自动 HTTPS）                                             │
   │   ├─ 静态网站  /srv/site/current  ← 原子切换的最新版本            │
   │   └─ /api /mcp /admin  →  app 容器                               │
   │                                                                  │
   │  app 容器（Node）                                                 │
   │   ├─ AI 销售对话（选型 / 参考价 / 留资 / 评级 / 转人工）            │
   │   ├─ MCP 接口（供外部 AI 查产品、报价、提交询价）                  │
   │   ├─ 后台 /admin（线索、业务闭环、内容、GEO 监测）                  │
   │   ├─ 销售→交付闭环：报价/PI、订单、库存、发货物流、售后            │
   │   ├─ 客户中心 /portal（确认 PI、查订单物流、申请售后）              │
   │   ├─ 内容智能体（定时选题 → 写稿 → 校验 → 审核 → 发布 → 重建网站） │
   │   └─ SQLite 数据库 + 文章 Markdown（持久化在 data/ 目录）          │
   └──────────────────────────────────────────────────────────────────┘
         │ 告警                      │ 调用                     │ WebAPI
   企业微信 / 飞书 / Webhook      大模型 API（Claude / OpenAI 兼容）   金蝶云星空
```

关键设计：

- **网站是静态页面**：速度快，搜索引擎和 AI 抓取器读取完整内容，服务器负载低。
- **AI 红线写在代码里**：价格只能来自公开价格档位，回复中出现金额会自动补上"仅供参考，以正式 PI 为准"。成本和底价根本不进系统，也就不存在泄露的可能。线索评级用固定规则计算，不交给模型判断。
- **没有大模型密钥也能运行**：此时自动切换为内置规则答复，可以先上线再接模型。

## 三、部署步骤（每个站做一遍）

以下以 LED 站为例；YR GRID 站把 `led-na` 换成 `grid-sea` 即可。

**1. 域名解析**：把域名（以及 `www`）的 A 记录指向服务器 IP。

**2. 安装 Docker**（服务器上执行）：

```bash
curl -fsSL https://get.docker.com | sh
```

**3. 上传代码并填写配置**：

```bash
mkdir -p /opt/yr-sites && cd /opt/yr-sites
# 把代码包解压到这里（或 git clone）
cd deploy/led-na
cp .env.example .env
nano .env        # 至少填写 DOMAIN、ADMIN_PASSWORD；建议填写 LLM_* 和 WECOM_WEBHOOK_URL
```

**4. 启动**：

```bash
docker compose -f ../docker-compose.yml --env-file .env up -d --build
docker compose -f ../docker-compose.yml --env-file .env logs -f app   # 看到 "site is live" 即完成
```

首次启动会自动把示例文章复制到 `data/news`，构建网站，再由 Caddy 申请 HTTPS 证书（1–2 分钟）。

**5. 验证**：

- `https://域名/`：网站
- `https://域名/admin`：后台（用 .env 里的账号密码登录）
- `https://域名/api/health`：返回 `"mode":"ai"` 表示大模型已接通，`"rules"` 表示规则模式
- `https://域名/llms.txt`：给 AI 读的站点目录

**6. 更新代码**：

```bash
cd /opt/yr-sites && git pull     # 或覆盖新代码包
cd deploy/led-na && docker compose -f ../docker-compose.yml --env-file .env up -d --build
```

文章和数据库都在 `deploy/led-na/data/`，更新代码不会丢。

**7. 备份**：

```bash
crontab -e
30 3 * * * /opt/yr-sites/deploy/backup.sh /opt/yr-sites/deploy/led-na >> /var/log/yr-backup.log 2>&1
```

建议再用 rclone 把备份同步到对象存储。

**可选：Cloudflare**。先用"仅 DNS"模式完成首次证书签发，再开启代理，SSL 模式设为 Full (strict)。

## 四、日常运营：后台 /admin

| 页面 | 用途 |
|---|---|
| 经营看板 | 今日 / 7 天 / 30 天成交额、订单数、客单价、网店下单转化率；每日成交柱状图；热销商品；库存预警；待付款、待发货、待处理售后、待审核评价（点数字直接进入对应列表） |
| 线索 | 按 A/B/C/D 评级排列，显示评级依据；可改状态；**「生成报价」一键把线索变成 PI 草稿**；可导出 CSV |
| 业务闭环 | 看板、报价/PI、订单、发货物流、售后、SKU 中心、库存/金蝶、客户（见第九节） |
| 对话 | 每段 AI 对话的完整记录。转人工的对话标为"接待"，打开后可以直接回复客户（见下方"人工客服"） |
| 内容 | 内容智能体写的草稿：审核、修改、发布、撤回；也可手动"立即生成一篇" |
| 网店 | 支付渠道状态、关闭超时未付款订单、邮件发送记录；运费模板（按国家分区、首重续重、体积重、满额包邮） |
| 优惠券 | 百分比或固定金额；满减门槛、总量和每人限用次数、有效期、限定品类；显示已使用次数。客户在结算页填写券码 |
| 评价 | 只有订单已签收的买家才能评价，每个商品一次；审核通过后在产品页显示（只显示名字和国家），可以公开回复 |
| 商品 / 品类 / 站点设置 | 商品自助上架、规格（SKU）、阶梯价、库存、图片、批量导入导出；保存后点「发布」，网站自动重建。列表里可以勾选后批量上架/下架、设为推荐或取消推荐，拖动行或直接填排序号调整顺序（越小越靠前）。推荐商品显示在网站首页"推荐产品"区，数量上限可设置（默认 8 个，0 = 不限） |
| GEO 监测 | 每周问 AI 搜索一遍买家常问的问题，记录我们有没有被提到、出现了哪些竞品 |

**AI 自动上架**（商品 → AI 自动上架）：
- **资料来源**：从金蝶拉取还没建 SKU 的新物料；上传供应商规格表（CSV / Excel，任意列名）；或直接粘贴产品资料。
- **AI 生成内容**：中英文名称、简介、卖点、参数、应用场景和搜索关键词。
- **自动核对**：认证和参数里的数字必须能在原始资料中找到，找不到的会被删除并列在"需要核对"里；夸大用语和不存在的品类也会被标出。
- **价格与条款**：价格、重量、起订量只取原始资料；质保和交期取页面下方设置的默认值。没有价格的商品按"仅询价"上架。
- **审核与上架**：默认生成草稿，员工点"审核并上架"检查后上架。开启"自动上架"后，AI 生成且没有任何需要核对的问题的商品直接发布；规则模式（未配置大模型）生成的草稿永远需要人工审核。
- **定时拉取**：可选每 6 小时自动从金蝶拉取新物料并处理。

**弃购提醒**：同意接收营销邮件的客户，购物车闲置超过 24 小时会收到一封提醒邮件（每个购物车只发一次，超过 14 天不再提醒）。没有勾选同意的客户不会收到。

**素材仓库**（美工）：
- **管什么**：商品图片（JPG/PNG/WebP ≤25 MB）、视频（MP4/MOV ≤500 MB）、设计源文件（PSD/AI ≤300 MB，只存文件并显示缩略图）。
- **目录**：上传到商品时自动建"网站 / 型号 / 主图·副图·SKU 图·详情图·视频·源文件"目录；也可以自建文件夹，或整个文件夹拖进来。还有"公共素材"放品牌素材和可复用的图。
- **自动识别**：白底图、透明图、方图（主图候选）、长图（详情图）、低分辨率；配置大模型后还能识别场景图、生活方式图、信息图、尺寸图等。
- **检索**：按商品、类型、标签、格式、尺寸、上传人、日期组合搜索，支持以图搜图（查重、找原图）。
- **预览**：图片可滚轮缩放、拖动平移；两个版本可以并排对比；视频可在线播放，并把当前画面截成图片。
- **版本**：每次重新上传或处理都生成新版本，记录操作人、说明和提示词；可以回滚，也可以指定哪个版本是上架用的"正式版"。
- **批量**：打标签、移动、打包下载、删除、上架到商品。
- **回收站**：删除的素材默认保留 30 天，可恢复；彻底删除需要"彻底删除"权限。
- **容量**：默认上限 30 GB，按商品和类型统计；用到 80% 时推送企业微信。
- **水印**：文字或图片水印模板；"预览水印"加在后台预览图上，"成品水印"加在上架到网站的图片上，原图始终不变。
- **商品链接拉取**：粘贴供应商或工厂的商品页，读取名称、型号、描述和图片，自动放进商品目录；"竞品参考"只读文案，不下载图片。只访问公网地址。
- **上架到独立站**：勾选图片，选商品和位置（主图第几张 / 副图 / 详情图 / SKU 图）。网站用自动压缩的版本（最大边长和质量可设置）。上架前会检查尺寸、白底和比例。每次修改都保存为图片历史，商品页可一键恢复上一组图片。
- **图片处理**（素材详情页"图片处理"）：改尺寸（尺寸预设在"容量与设置"里维护）、一键导出多尺寸、白底、扩图（模糊延展或纯色）、调色（亮度 / 饱和度 / 对比度 / 自动色阶 / 按参考图统一色调）、去噪锐化和 2 倍放大、局部修图（在图片上涂抹污点后处理）。这些都在服务器本地完成，不需要外部服务。结果保存为新版本（可回滚）或另存为新素材。
- **AI 抠图 / 换背景**：需要在 `.env` 配置 `IMAGE_AI_KEY`（remove.bg 的 API Key；用其他兼容服务时再设 `IMAGE_AI_BASE_URL`）。换背景时先抠图，再在服务器上把商品放到指定底色或素材库里的场景图上。没配置时这两个选项显示为不可用。
- **任务中心**（/admin/tasks）：在素材列表勾选多张图片后"批量处理 → 加入任务"，任务在后台逐项执行，可以离开页面。任务详情显示每张图片的结果和失败原因，可暂停、继续、取消、重试失败项；服务重启后未完成的任务会自动继续。有失败项的任务会出现在美工工作台的待办里。
- **AI 合规检查**：素材详情页一键检查正式版是否有水印、第三方品牌标志、夸大宣传文字、可识别的人物或模糊变形（需要配置支持图片的大模型）；有问题的图片上架时会再次提示。
- **标题与提示词**（/admin/copy）：选择商品、语言（英文 / 中文）和方向（搜索优化、简洁、批发 / 工程采购、突出卖点），可填客户常搜的词和参考页面链接（只读取标题），生成标题建议；违禁词黄色（提醒）或红色（禁止）标出。点"应用到商品"写入商品名称，标题历史里可以一键改回。未配置大模型时按商品资料生成。提示词页有模板库（内置模板可复制修改）和"AI 优化提示词"。
- **违禁词**：内置绝对化用语、无法兑现的保证、医疗功效、广告法用语等，可停用或新增。**每次保存商品**（后台编辑、表格导入、AI 自动上架）都会检查名称、简介、卖点、关键词和应用场景：禁止级的词不能保存，提醒级的词会提示。
- **预览**：商品编辑页"手机 / 电脑预览"同时显示网站商品页在手机和电脑上的样子。
- 服务器需要 ffmpeg 才能生成视频封面和预览（Docker 镜像已自带）。

**工作台与岗位**：
- 登录后进入"工作台"：上方是本岗位的关键指标，中间是"今天要处理的事"（点一下进入对应记录），下方是常用入口；页头显示待办数。
- 内置岗位：管理员、销售、财务、仓库/物流、内容运营、客服、美工、运维。
- 需要不同权限组合时，在"账号权限 → 管理岗位"新建岗位，可复制内置岗位后增减。权限细到"只看 / 处理 / 导出 / 删除 / 审批"。
- 一个人可以同时有多个岗位，权限合并。
- 只有"账号与岗位"权限的人只能授予自己拥有的权限，不能创建或修改管理员。
- **按站点分配**：两个站是独立部署、各自有账号，"只管 YR GRID"就是只在 GRID 后台给他开账号。
- **操作日志**（运维、管理员可看）：记录每一次修改、登录、登录失败和被拒绝的越权操作（密码不记录），可按人员、模块、结果、日期筛选并导出 CSV。

**后台语言**：
- 右上角按钮可以在中文和 English 之间切换，页面不跳转。
- 每个账号的选择会记住，下次登录自动使用；也可以在"修改密码"页设置。
- 管理员可以在"系统"页设置默认语言，给没有自己设置的同事使用。
- 英文界面下，商品的中文名称、客户的中文消息等资料保持原样，只翻译界面文字；导出的商品表格列名也跟随语言。

**人工客服**（对话 → 接待）：
- 客户要求转人工，或 AI 判断需要人工时，对话列表会标出"接待"，同时推送企业微信通知。
- 业务员打开对话直接回复即为接管；客户在网站聊天框里实时看到，显示业务员的名字（只显示名，不显示账号）。
- 人工接待期间 AI 不再回复。客户发来新消息时，列表显示"客户等待回复"，并推送企业微信通知（每段对话每分钟最多一次）。
- 同一时间只有一位同事能接待；点"交还 AI"或 30 分钟没有回复后，自动交还 AI。
- AI 重新接手时能看到业务员之前的回复，不会前后矛盾。
- 业务员页面每 4 秒自动刷新新消息。

**线索评级规则**（`shared/sales-engine.js` 的 `scoreLead`，可按业务调整）：企业邮箱 +2，留了公司名 +1，数量 ≥1000 +3 / ≥200 +2，一个月内采购 +2 / 三个月内 +1，工程、渠道或 OEM 客户 +2，留了电话或 WhatsApp +1。7 分及以上为 A，4–6 分为 B，2–3 分为 C，其余为 D。

**转人工的触发条件**：OEM/ODM、议价、超出公开价格档位的大单、合同条款、投诉、客户主动要求，以及 YR GRID 的工商业项目方案和渠道合作。每个站的完整规则在 `server/profiles/*.json` 的 `handoffRules`。

## 五、SEO / GEO 内容智能体

### 工作流程

1. **定时触发**：默认每周一、三、五 9:00（北京时间），按 `CONTENT_LANGS` 每种语言各写一篇。
2. **选题**：从行业 RSS 新闻、选题库（`server/profiles/*.json` → `content.topics`）和已发布文章中，挑一个买家最关心、且没写过的题目。
3. **写稿**：每篇都按 AI 回答引擎偏好的结构来写：
   - 开头是"简短回答"；
   - 用买家会问的子问题做小标题；
   - 配 3–5 条 FAQ（自动生成 FAQ 结构化数据）；
   - 链接到相关产品页；
   - 引用新闻时附原文链接。
4. **自动校验**：
   - 自动删除站内不存在的链接、不是来自所给新闻源的外链，以及不存在的产品；
   - 出现以下情况会强制留作草稿：最高级用语（最好、第一、保证收益等）、金额数字、没有来源的百分比、篇幅不足、开头没有"简短回答"。
   - 校验不通过时，智能体会先自我修正一次。
5. **审核发布**：
   - `CONTENT_AUTO_PUBLISH=false`（默认）：草稿进入后台"内容"页，由人审核后点"保存并发布"；
   - 改为 `true` 后，通过校验的文章自动发布，未通过的仍会留作草稿。
6. **上线与推送**：发布后自动重新构建网站，新版本原子切换上线。sitemap、llms.txt 和 RSS 同步更新，并通过 IndexNow 通知 Bing 等搜索引擎（ChatGPT 搜索和 Copilot 都用 Bing 的索引）。

### 新品自动推广（GEO）

商品**第一次**发布上线时（手动点"发布到网站"或 AI 自动上架都算），系统会自动：
1. 通过 IndexNow 通知搜索引擎收录新产品页（需要配置 `INDEXNOW_KEY`）；
2. 把买家可能问 AI 的问题（如"哪些厂家供应 xx？"）加入 GEO 监测，每周检查我们有没有被提到；
3. 让内容智能体写一篇产品文章：参数、应用场景、选型要点。是直接发布还是留作草稿，按 `CONTENT_AUTO_PUBLISH` 决定。不想自动写文章，设 `CONTENT_PROMOTE_NEW=false`。

执行记录在后台"商品 → AI 自动上架"页下方。同一商品重复发布不会重复推广。

### 建议节奏

- **上线后前 1–2 个月**：保持人工审核。每篇检查三件事：参数对不对、有没有夸大、观点是否站得住。
- 草稿质量稳定后再开启自动发布，之后每周抽查。
- 业务人员每月往选题库补 5–10 个客户真实问过的问题。这是最有价值的选题来源。

### 需要配置

- `INDEXNOW_KEY`：任意 32 位字母数字。上线后在 Bing Webmaster Tools 提交 sitemap。
- Google Search Console：验证域名并提交 `https://域名/sitemap.xml`。
- RSS 源：`content.feeds` 里预置了几个行业媒体，部署后请在后台"运行记录"中确认能否抓取，抓取失败的源直接删除或替换即可。
- GEO 监测：建议用带联网搜索的模型，例如 Perplexity（OpenAI 兼容），配置 `GEO_LLM_*`。监测问题和竞品名单在 `content.geo` 里维护。

## 九、销售到交付闭环

从线索到售后，在同一套后台里完成，状态和编号规则统一定义在 `shared/dictionary.js`（说明见 `docs/数据字典.md`）。

| 环节 | 谁操作 | 系统做什么 |
|---|---|---|
| 1. 生成报价 | 业务员在「线索」点「生成报价」 | 自动建客户档案，带入产品和数量，单价默认取 SKU 参考价 |
| 2. 发送 PI | 业务员核对明细、条款后点「保存并发送」 | 生成客户确认链接和中英文邮件模板（复制发送） |
| 3. 客户确认 | 客户打开链接，点「确认下单」 | 自动生成订单（待付定金），推送金蝶销售订单，企业微信通知 |
| 4. 收定金 | 财务/业务在订单页「登记收款」 | 定金到账后订单自动进入「生产/备货中」 |
| 5. 备货完成 | 在订单页推进到「待发货」 | 尾款未收清时醒目提示（按付款条款） |
| 6. 发货 | 创建发货单，填写船司/快递、柜号、ETD/ETA | 按 SKU 装箱数据自动算箱数、体积、毛重 |
| 7. 物流跟踪 | 在发货单添加动态 | 「运输中」→ 订单自动变为已发货；「已签收」→ 订单自动变为已签收 |
| 8. 售后 | 客户在客户中心或 AI 客服提交 | 生成售后单并通知；审核后可一键创建补发单 |

**客户中心 `/portal`**：客户可以通过 PI 链接、订单页链接，或「订单号 + 邮箱」进入，查看 PI、订单进度、物流动态，提交售后。页面语言跟随客户档案（中文/英文）。

**AI 客服联动**：客户在网站聊天里说"我的订单到哪了"或"货物损坏"，AI 会先核对订单号和邮箱，再回复进度和物流，或直接创建售后单。两者不匹配时不透露任何订单信息。

**上线前补充**：
- 在 SKU 中心为每个型号填写装箱数据（每箱数量、体积、毛重）、HS 编码和金蝶物料编码，有规格差异的建 SKU 变体（例如 `YR-HB-U2-150-50K`）。
- 在 `sites/*/src/data/site.json` 增加 `"bank": {...}` 后，PI 上会显示收款账户；不填时 PI 提示"账户由业务员另行发送，请电话核实"。这是为了防范冒充收款的诈骗。
- 配置 `SMTP_URL` 后，合同签署链接、签署确认、网店订单等邮件自动发出（未配置时进入后台"网店 → 邮件记录"，不会真的发送）。PI 链接和邮件模板仍可由业务员复制发送。

### AI 议价与电子合同

**谁定规则**：财务在「业务闭环 → AI 议价 → 授权政策与底价」设置：
- 每个信用级别的最大折扣；
- AI 可以直接成交的最大订单金额；
- 议价轮数和报价有效期；
- AI 可以接受的付款方式和价格条款；
- 每个 SKU 的底价。

这些数字不会出现在网站、AI 的提示词或 MCP 里。AI 只能拿到系统算出来的最终报价。

**信用级别只看可核实的信息**：A = 付过款的老客户，B = 企业邮箱，C = 免费邮箱（Gmail 等）。客户在聊天里自称"大客户"不会影响级别。

**AI 怎么谈**：
1. 客户要下单或砍价时，AI 先要企业邮箱，再调用报价工具。
2. 客户要价低于授权时，系统给出还价：第一轮最多让出一半授权，第二轮起才到上限，而且不会低于底价。
3. 超过金额上限、要求信用证等需审批的付款方式、DDP 等条款，或议价超过轮数时，进入「待审批」，并在企业微信通知。

**审批**：财务打开待审批的报价，可以修改单价（不能低于底价）后批准，系统自动生成合同并发给客户；也可以拒绝，系统会邮件通知客户。

**合同**：
- 客户接受后，系统按「合同模板」生成 PI 和销售合同。模板由管理员维护，请法务审核。
- 合同内容生成后即冻结，记录 SHA-256 指纹。
- 签署链接**只发到报价时的邮箱**，不会出现在聊天里，这样可以确认签署人能收这个邮箱的邮件。
- 客户在网页上输入姓名、职务，勾选同意后完成电子签署。系统记录时间、IP、浏览器和签名指纹，自动生成订单（待付定金），并推送金蝶。
- 业务员也可以在任意 PI 页面点「生成合同并发给客户签署」。已有合同的 PI，客户必须签合同才能下单。
- 未签署的合同可以作废，需填写原因。已签署的合同不能修改。

**MCP**：采购方的 AI 智能体也可以通过 MCP 询价、获取报价，规则与网站聊天相同；合同同样只发到报价时的邮箱。

## 九（附六）、仓库 / 物流（后台"仓库"菜单）

- **发货台**：列出待发货的订单（含部分已发的）和待发数量、箱数、体积。勾选后可以打印**拣货单**（按 SKU 汇总数量、箱数和库存，再按订单列出明细，留拣货人 / 复核人签字栏）。
- **批量发货**：在发货台每行填物流商和运单号，一次提交；或把"订单号, 物流商, 运单号, 方式"粘贴导入（可从物流商系统或表格复制）。每单生成发货单、标记为运输中并通知客户；每行单独成功或失败，并显示原因。
- **库存与出入库**：可售 = 现有 − 未发货订单占用（已部分发出的不再占用）。本地库存模式下，发货时自动扣减库存；入库、出库、退货入库、盘点在这里登记，每笔都有结存和操作人。接了金蝶时库存以金蝶为准，只在这里设置安全库存。
- **安全库存**：每个 SKU 可以单独设置，留空用默认值；低于安全库存的标红，每天 8:00 推送企业微信，仓库工作台也会提醒。
- **物流商对比**：输入国家和重量，按运费模板列出各方式的运费和时效；并统计每个物流商的发货单数、已签收、平均运输天数和异常率。

## 九（附五）、财务（后台"财务"菜单）

- **应收账款**：所有没收齐款的订单，显示到期日和逾期天数；按客户汇总未收、已逾期和账龄（0–30 / 31–60 / 61–90 / 90 天以上）；可导出表格。到期规则：定金在下单后 N 天内（默认 7 天，可改）；尾款按付款方式在发货前、见提单副本（发货后 7 天）或发货时到期。每天 9:00 把新逾期的订单推送企业微信，财务工作台也列出逾期订单。
- **对账**：选择 Stripe、PayPal（直接读取对方的到账记录）或粘贴银行流水（日期, 摘要, 金额, 币种），与系统登记的收款逐笔核对，列出"对方有、我们没记""我们记了、对方没有"和"金额不一致"。银行流水按摘要里的订单号匹配，没有订单号时按金额和日期（前后 3 天）。每次对账都有记录。
- **财务报表**：近 12 / 24 个月每月的订单数、订单金额、实收（在线 / 电汇）、退款、净收款、优惠和运费，可导出。
- **收款单同步金蝶**：接了金蝶时，每次登记收款（含网店在线付款）自动生成金蝶收款单（AR_RECEIVEBILL）；客户需要先随订单同步到金蝶，失败的每小时补推，也可以手动推送。单据类型和结算方式编码可用 KD_RECEIPT_BILLTYPE、KD_SETTLE_TT、KD_SETTLE_ONLINE 调整，实施时请按贵司账套核对。
- **商业发票和装箱单**：订单页"商业发票""装箱单"按客户语言生成，可打印或存为 PDF。装箱单按 SKU 中心的装箱数据计算箱号（连续编号）、净重、毛重、体积，并生成唛头；缺少装箱数据的型号会提示。

## 九（附四）、运营（后台"运营"菜单）

- **经营数据**：今天 / 7 天 / 30 天 / 90 天的访客、页面浏览、商品浏览、加入购物车、网店订单、下单转化率、询价和询价率、在线成交额（已付款）；近 30 天趋势图；访客来源和热门页面。数据来自网站自己的统计：每个页面发一次很小的统计请求，不用第三方统计代码，不记录个人信息（访客按当天去重），机器人和后台页面不计入。
- **商品数据**：每个商品的浏览、加购、加购率、订单、转化率、件数、销售额，可按任意一列排序、导出表格；商品列表里也直接显示近 30 天数据，可"按数据排序"。浏览多但没人加购、加购多但没下单的商品会给出提示，也出现在运营工作台。
- **推广活动**：每个渠道建一个活动（名称、代码、来源、方式、落地页、花费），自动生成带 UTM 参数的推广链接。通过链接进来的访客在 30 天内的询价和下单都记到该活动上；显示访客、询价、订单、已收款成交额、投入产出比、单个询价成本、获客成本。链接里出现但还没建活动的代码也会列出来。
- **限时折扣 / 满减**：设置开始和结束时间后自动生效、自动结束；打折可以针对全部商品、指定品类或指定型号；满减按门槛金额减免。购物车和结算自动使用当时最划算的一个活动（可以和优惠码同时用，总优惠不超过商品金额），订单里记录用了哪个活动；商品页显示促销标签，网站首页出现"正在促销"专区。
- **首页专区**：网站首页依次是"正在促销"（自动）、"新品上市"（自动取最近上架的商品，或手动指定型号和顺序，也可以关闭）、"推荐产品"。修改后发布网站生效。
- **邮件营销**：写邮件（纯文本，`{{name}}` 替换为客户称呼），按客户标签、类型、VIP、语言选收件人；只发给注册时同意接收营销邮件的客户。可以先发测试邮件；正式发送在任务中心逐封进行。每封邮件带一键退订链接（同时有 List-Unsubscribe 邮件头），退订后不再收到；统计已发送、打开、打开率、退订，并可查看每位收件人的情况。需要配置 SMTP_URL 才会真正发出。
- **关键词与 AI 提及**：维护要做排名的关键词和目标页面，每次记录排名（Google / Bing / 百度），或把 Ahrefs、Semrush 等工具导出的"关键词, 排名, 网址, 搜索引擎, 日期"粘贴导入；显示最新排名、上升或下降、历史趋势。AI 搜索提及率按周显示（来自 GEO 监测）。
- 导出的表格列名跟随后台语言（中文 / English）。

## 九（附三）、业务（销售）

- **线索归属**：每条线索有负责人。普通销售只看到**自己的线索和公海**，"销售主管"岗位（或有"线索：查看全部"权限的人）看到全部，可按负责人筛选。
- **自动分配**（"线索 → 分配规则与提醒"，主管可设）：先按规则（国家列表、品类）分配，没有匹配的规则时在勾选的销售之间**轮流分配**；也可以设为不自动分配，全部进公海。
- **公海**：未分配的线索和超过 N 天（默认 7 天）没有跟进的线索进入公海，任何销售都可以"领取"；负责人可以转交或放回公海，所有变动都有记录。
- **跟进记录**：线索详情页记录电话 / 邮件 / WhatsApp / 见面，填写下次跟进时间；到期的跟进显示在"待跟进"和工作台待办里。
- **报价模板**：在任意报价页"存为模板"（条款 + 产品组合），以后"套用模板"一键带入。
- **报价跟踪**：客户打开报价单（PI）或合同链接会被记录（同事预览不算），报价页显示打开次数和时间；客户第一次打开时推送企业微信，工作台提示"可以跟进了"。
- **客户 360**：客户页集中显示联系人、询价、跟进、聊天、报价（含打开记录）、合同、付款、售后、评价；可设置客户类型（经销商 / 工程商 / 终端客户）、VIP、标签、生日、负责人。客户列表可按类型、标签、VIP 筛选。
- **生日和节日提醒**：客户生日和节日（在分配规则页维护）前 7 天出现在销售工作台。
- **销售业绩**："线索 → 销售业绩"显示每人每月的新线索、跟进、报价、线索→报价、成交、报价→成交、成交额、回款和目标完成度，近 6 / 12 个月对比；主管设置每人每月目标。

| 系统状态 | 版本、运行时间、内存、磁盘、数据库；备份列表（下载、**恢复演练**）、备份记录 |

## 九（附）、数据库备份与恢复

所有业务数据（商品、订单、客户、合同、对话）都在一个 SQLite 数据库文件里（容器内 `/data/db.sqlite`）。

- **自动备份**：
  - 每天 `BACKUP_HOUR` 点（默认 3 点）做一次在线快照，备份时网站照常访问。
  - 快照压缩为 `.sqlite.gz`，保存在 `BACKUP_DIR`（默认 `/data/backups`），保留最近 `BACKUP_KEEP` 份（默认 14）。
  - 每份备份都会解压并做完整性检查（相当于一次恢复演练）。检查不通过记为失败，并推送企业微信通知。
- **异地备份（强烈建议）**：
  - 设置 `BACKUP_CMD`，每次备份完成后执行，`{file}` 会替换为备份文件路径。例如 `rclone copy {file} oss:yr-backups/led` 或 `aws s3 cp {file} s3://yr-backups/led/`。
  - 命令执行失败会记为备份失败并通知。
  - 不配置时，备份和数据库在同一块磁盘上，服务器损坏会一起丢失。
- **后台"系统"页（仅管理员）**：
  - 显示版本、运行时间、数据库和磁盘大小、最近备份和后台任务记录。
  - 可以手动"立即备份"、下载备份文件。
  - 超过 36 小时没有成功备份，或磁盘剩余不足 2 GB 时会显示警告。
- **恢复步骤**：
  1. `docker compose stop app` 停止服务；
  2. 把当前的 `/data/db.sqlite` 改名保留（同时删除 `db.sqlite-wal` 和 `db.sqlite-shm`）；
  3. `gunzip -c yr-led-<时间>.sqlite.gz > /data/db.sqlite`；
  4. `docker compose start app`，启动时自动执行数据库迁移；
  5. 在后台核对最近的订单和商品。最后一次备份之后的数据需要人工补录，所以备份频率按业务量决定（可以把 `BACKUP_HOUR` 配合定时任务改为更频繁）。

## 十、金蝶云星空对接

| 方向 | 内容 | 时机 |
|---|---|---|
| 网站 → 金蝶 | 客户（BD_Customer）、销售订单（SAL_SaleOrder，保存为**创建状态**，由业务在金蝶里提交审核） | 客户确认 PI 时自动推送；也可在订单页手动推送或重试 |
| 金蝶 → 网站 | 即时库存（STK_Inventory），按物料编码对应到 SKU | 每 `ERP_SYNC_MINUTES` 分钟一次，后台可手动立即同步 |
| 金蝶 → 网站 | 物料列表（BD_MATERIAL），用来核对 SKU 与物料编码 | 后台「库存 / 金蝶」页手动拉取 |

**配置步骤**：

1. 在金蝶云星空的「管理中心 → 第三方系统登录授权」新增应用，记下应用 ID 和应用密钥，并绑定一个集成用户。该用户需要客户新增、销售订单新增、即时库存查询、物料查询的权限。
2. 在 `.env` 中设置 `ERP_MODE=kingdee`，并填写 `KD_BASE_URL`、`KD_ACCT_ID`（数据中心 ID）、`KD_USERNAME`、`KD_APP_ID`、`KD_APP_SECRET`、`KD_ORG_NUMBER`（销售/库存组织编码）。
3. 核对币别编码（`KD_CUR_USD` 等）和销售订单单据类型（`KD_SO_BILLTYPE`），使其与贵司金蝶基础资料一致。
4. 重启 app 容器后，在后台「库存 / 金蝶」页依次点「测试连接」「拉取金蝶物料，核对编码」，把没有对上的物料编码填进 SKU 中心。
5. 用一张测试 PI 走一遍：客户确认 → 订单页出现金蝶销售订单号 → 在金蝶里找到这张单据。

**注意**：
- 字段按金蝶**标准版**数据模型编写。如果贵司金蝶做过二次开发、增加了必填字段，推送失败时订单页会显示金蝶返回的具体字段错误。请金蝶实施顾问对照 `server/src/ops/erp/kingdee.js` 中的 `buildSalesOrder()` 和 `buildCustomer()` 调整。
- 网站服务器在海外：金蝶公有云（ik3cloud.com）可以直接访问；私有部署需要开放公网 HTTPS 访问，或配置 VPN / 白名单。
- 运费和整单折扣写在销售订单备注里，不拆成单独的分录行。
- 尚未接金蝶时，`ERP_MODE=local` 在 SKU 中心直接维护库存；`ERP_MODE=mock` 用模拟数据把整套流程跑通，适合培训和演示。

## 十一、常见问题

- **AI 回答不准**：先检查 `catalog.json` 里有没有这条信息。AI 只引用目录和 `facts` 里的内容，资料缺了它会说"由业务工程师确认"。
- **想调整 AI 的话术或规则**：改 `server/profiles/*.json`，重启 app 容器即可生效。
- **文章发布后网站没变**：后台"内容"页下方的"运行记录"会显示构建结果。构建失败时线上保持旧版本，不会出现空白页。
- **控制大模型费用**：对话默认上限为每 IP 每分钟 20 条（`RATE_LIMIT_PER_MIN`）；写稿可以单独配置一个便宜的模型（`CONTENT_LLM_*`）。
